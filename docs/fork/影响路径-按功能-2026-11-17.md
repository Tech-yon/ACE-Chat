# 功能影响路径总表（按功能分立 · 2026-11-17）

> **用途**：改任何东西之前，先在这里找到对应功能，看清「哪些输入 → 哪些代码 → 哪些缓存 → 哪些输出」。
> 每条路径都给出：**入口 / 生效链 / 缓存 / 波及面 / 常见断点**。
> 配套：`SPEC-技术大纲`（不变量、根因库）、`项目大纲`（设置清单）、`FRONTEND-细则`（迁移看板）。

记号：`→` 调用/数据流；`⟲` 缓存；`✖` 失效点；`⚠` 易错点。

---

## 〇、全局分层（先看这张）

```
用户操作 / 游戏事件 / 网络包 / 磁盘文件
        │
        ▼
   CommsConfig（内存配置：全局 + 当前卡 + 预览态）
        │
        ├──► CommsState（消息队列 / 舞台 / 当前说话人 / 肖像）
        │
        ├──► CommsHud.render（每帧：聊天框 + 形象框 + 文字 + 调色/滤镜）
        │         └── PortraitSource → CardTextures / SkinBustRenderer
        │                       └── PortraitGrade（异步烘焙）
        │
        └──► 保存：client.json（全局） + cards/*.json（形象/文字/调色）
```

**六个共享缓存（改任何相关功能都要想它们）**

| 缓存 | 位置 | 键 | 失效方式 |
|---|---|---|---|
| 卡配置 | `CommsConfig.appliedCard` | 卡名 | `applyCard()` / `selectCard()` |
| 角色身份 | `CardCharacter.CACHE` | 卡名 + mtime | `clearCache()`、写 `character` |
| 皮肤/立绘纹理 | `CardTextures`（LRU 36MB） | 文件 + mtime | `clearAll()` |
| 形象来源 | `PortraitSource.CACHE` | UUID + name + mtime + TTL | `clear()` / `invalidate(uuid)` |
| 调色烘焙 | `PortraitGrade` | 纹理 + `gradeKey()` | `invalidate()` |
| HUD 行缓存 | `CommsHud.cachedLines` | 内容版本 + 折行宽 | 版本变化自动失效 |

## 一、聊天框（显示 / 布局 / 样式）

**入口**
- 配置：`chat.*`（`hudEnabled`、`boxWidth`、`maxLines`、`centerXOffset`、`topYOffset`、`backgroundAlpha`、颜色、间距、内边距、边框、停留秒数）
- 状态：`CommsState.displayed()`、`CommsState.entries()`、`version()`
- 屏幕：`Minecraft.getWindow()` 的 GUI 尺寸

**生效链**
```
CommsHud.render
 └─ renderInternal
     ├─ displayed = CommsState.displayed()
     ├─ lines = chatLines(font, entry, boxWidth)   ⟲ cachedLines(version, wrap)
     ├─ rect = chatRect(guiW, guiH, lines.size(), chatEffectiveWidth(guiW))
     │        ├─ chatEffectiveWidth：boxWidth ∩ (形象框左边缘 − 右间距)
     │        └─ chatRect：居中 + centerXOffset，再夹到左右边距；y = 6 + topYOffset
     └─ drawChat(lines, rect)：背景（alpha/颜色）→ 名字（名字颜色）→ 符号 → 正文 → 边框
```

**缓存**
- `cachedLines`：内容版本或折行宽度变了才重排；
- `CommsState.version()`：入队/出队/舞台切换都会 +1。

**波及面**
- 改 `boxWidth`：聊天框宽度、可用折行宽、与形象框的间距；
- 改 `chatEffectiveWidth / portraitLeftEdge`：聊天框和形象框会互相挤压；
- 改 `maxLines`：HUD 高度、折行条数、`chatRect` 高度；
- 改全局聊天字段：所有卡共用（卡不存 `chat`）。

**常见断点**
- 预览区看起来“没变化”：预览宽度被形象框左边缘夹住（现已改为展示预览 + 屏幕示意区分）；
- 背景不透明：`backgroundAlpha` 是 0~1，UI 用百分比；
- 字被裁：`clipToFrame` + 内边距。

## 二、聊天内容来源（谁的消息能进 HUD）

**入口**
- 原版聊天事件：`ClientEvents` / `ModClientEvents` 拦截
- NCR 系统消息：`NcrChat.parse` → `CommsState.routeNcr`
- 舞台台词：`StagePlayer` → `CommsState.stageShow`
- 预览：`CommsState.preview`（G 键）

**生效链**
```
ChatEvent（ClientEvents 判定「玩家消息走原版」）→ CommsState.route / routeText
   ├─ 「玩家消息走原版」→ ClientEvents 直接放行原版（不在 route 内）
   ├─ 舞台占用（stageActive）→ 排队，等演出结束再轮播
   ├─ NCR 解析（若开启）→ routeNcr 转成玩家消息
   └─ 入队 ENTRIES → version++ → 由 tick 轮播
```

**波及面**
- 改 `route` 判定：会影响“哪些消息显示/走原版/丢队列”；
- 改 `stageActive`：演出期间普通聊天是否被压住；
- 改 `tick`：每条停留时长、队列推进、消失音。

**常见断点**
- 消息不显示：`vanillaPlayerChat` 开着、或舞台忙、或 HUD 关闭；
- NCR 消息假头像：名字匹配到了错误对象（见第十八节）。

## 三、名字与符号渲染

**入口**
- `CommsConfig.displayName(name)`（显示名映射）
- `CommsConfig.nameColor(uuid, name)`（条目/uuid/名字）
- `CommsConfig.nameStyleFor(...)`、`chatNameMaxWidth`、`chatSymbolPadding`、`chatSymbolPad()`（符号颜色已取消，跟随名字色）

**生效链**
```
chatLines → buildLines：
  nameFor(display) → displayName 映射
  nameStyleFor → 名字颜色（nameColors 优先，其次 chatNameColor）
  符号「<」「>」→ 跟随名字颜色（v0.1.3.3 起无独立设置；HUD / 原版左栏 / 注入历史一致）
  正文 → 折行（ChatLayout）
```

**波及面**
- 名字颜色条目是**按卡**的（条目名＝卡名），只在该卡发言时命中；
- 改 `nameFor`：所有消息的显示名；
- 改 `buildLines`：换行、符号、首行结构。

**常见断点**
- 改了颜色不生效：条目名与说话人对不上（卡名 vs 玩家名）；
- 名字超宽：`chatNameMaxWidth` 截断。

## 四、名字颜色（卡级条目）

**入口**
- `CommsConfig.nameColors`（List<NameColor>：uuid/name/color/note）
- `CommsConfig.cardNameColor`（本卡默认名色，"RRGGBB"，空=跟随全局；v0.1.3.4）
- 工坊「文字」页：新增 / 改色 / 删除 / 本卡名字颜色 / 复制
- 旧界面「名字」页

**生效链**
```
nameColors / cardNameColor ⟲ 随卡保存（cards/*.json）
   └─ resolvedNameColor(uuid, name)：
       1) 条目 uuid 匹配 → color
       2) 条目 名字匹配（忽略大小写）→ color
       3) 本卡 cardNameColor（未设置则跳过）
       4) 回退全局 chatNameColor
```

**波及面**
- 改匹配顺序：影响同名玩家/多卡同名；
- 条目名写错：永远不命中，会落到本卡默认色/全局默认；
- `applyCardData` 必须保留 nameColors 与 cardNameColor（当前随卡）；
- 演出时说话人卡被强制套用（`autoApplyCardFor`），所以本卡色直接生效。

**常见断点**
- “改一次颜色生成多条”：回调里 `add()` 而不是更新对象（已修）；
- 删除后仍变色：条目未随卡保存/缓存未刷新。

## 五、形象框（几何 / 外观 / 面板 / 边框）

**入口**
- `portrait*.get()`：宽高、缩放、XY 偏移、锚点比例、不透明度、亮度、蒙版、背景板、面板、边框、照片模式
- `CommsConfig.effectivePreviewCard()` / `previewing()`
- `CommsState.portrait()` / `speaker()`

**生效链**
```
portraitRect(guiW, guiH)
  = 比例锚点 × (屏幕 − 卡尺寸) + 偏移；缩放 = portraitScale
drawPortrait：
  背景板 → 面板 → 立绘/皮肤（PortraitSource）→ 边框 → 文字元素（drawElements）
```

**波及面**
- 改 `portraitRect`：聊天框有效宽度（`portraitLeftEdge`）、点击区域、屏幕示意；
- 改缩放/宽高：文字元素的 `elementScale` 基准；
- 改面板/边框：死亡覆盖、预览、演出共用。

**常见断点**
- 形象框跑到屏幕外：锚点比例 + 偏移叠加；
- 文字跟着错位：文字位置按卡片缩放换算，改缩放会连带文字。

## 六、皮肤 / 立绘解析（最容易串的一条链）

**入口**
- 卡：`CardCharacter.read(card)` → `{skin, portrait, boundPlayer, displayName}`
- 文件：`ACE_config/skins_slim|classic`、`portraits`
- 玩家：游戏 profile 皮肤

**生效链**
```
PortraitSource.resolve(mc, uuid, name)  ⟲ CACHE(uuid + stamp)
  ├─ 卡里有 skin/portrait（且 boundPlayer/预览）→ CardTextures 加载文件
  ├─ 否则 → 玩家 profile 皮肤
  └─ 兜底 → 默认皮肤
PortraitGrade.gradedOrOriginal(source)  ⟲ 烘焙（纹理 + gradeKey）
SkinBustRenderer：按照片模式裁切/缩放
```

**失效点**
- `CardTextures.clearAll()`（素材变更/切卡）
- `PortraitSource.clear() / invalidate(uuid)`（换卡/换皮）
- `CardCharacter.clearCache()`（character 段写入）

**波及面**
- 改解析顺序：预览/演出/死亡覆盖全变；
- 改缓存键：切卡后仍显示旧皮肤（本轮已修 `selectCard` 全清）；
- 改 `preferLocal`：多人同步时用远程还是本地卡。

**常见断点**
- 演出里显示成玩家自己：`boundPlayer` 判定 / `portraitOrSelf` / 卡皮肤失效回退；
- 改皮肤不刷新：mtime 没变（同秒内覆盖文件）。

## 七、调色 / 双色调

**入口**
- `gradeEnabled`、`gradeBrightness/Contrast/Saturation/Hue`、`duotoneEnabled/Dark/Light/Amount`
- `CommsConfig.gradeKey()`（参与烘焙缓存键）

**生效链**
```
PortraitGrade.gradedOrOriginal：
  gradeKey = 所有调色参数拼接
  ├─ 缓存命中 → 直接用
  ├─ 未命中 → startBake（异步，取当前纹理→资源→profile）
  └─ 失败 → 5 秒后重试（不永久拉黑）
PortraitGradeMath：RGB↔HSL、亮度/对比/饱和/色相、双色调映射
```

**波及面**
- 任何调色参数 → `gradeKey` → 重烘焙；
- 烘焙失败 → 显示原图（偏色即“没烘焙上”）；
- 双色调暗/亮色是取色值，改一颗会整体偏色。

**常见断点**
- 时好时坏：烘焙失败重试 / 纹理未加载完；
- 改了不生效：`invalidate()` 没调，或 `gradeKey` 没包含新参数。

## 八、滤镜

**入口**
- `filterEnabled`、`filterName`（`builtin:*` 或模板名）、`filterAlpha`、`filterBlend`、`filterTint`、滤镜亮度/对比/饱和/色相
- `PortraitFilters.BUILTIN_IDS`、`CommsConfig.filterTemplates`、`ACE_config/filters`

**生效链**
```
PortraitFilters.apply(...)（在形象绘制后叠加）
  ├─ builtin:scanlines / scanlines_h / grain / vignette / duotone / dots
  └─ 模板：参数 + 可选图片
```

**波及面**
- 改滤镜顺序/混合模式：整体画面；
- 改模板：旧卡按 `filterName` 找不到会回退。

**常见断点**
- 滤镜不显示：`filterEnabled` 关、强度 0、或模板名不存在（找不到就整帧不画，不回退）
- 换卡后滤镜串：模板列表属于全局，卡里只存名字。

## 九、文字元素

**入口**
- `textElements`：内置 4（名字/生命/饥饿/护甲）+ 自定义
- 字段：content、size、x/y、maxWidth、horizontal/vertical、shadow、visible、color、kind

**生效链**
```
drawElements：
  for element in (内置 + 自定义，按 kind 去重)
    可见性 → 内容占位符（%player_name% 等）→ elementScale(卡宽)
    → 位置（对齐 + x/y×缩放）→ 颜色（elementTint/applyElementTint）→ 阴影
  记录 lastElementRects（供拖动/命中）
```

**波及面**
- 改 `elementScale`：所有文字位置/字号跟着卡片缩放；
- 改内置元素：`ensureBuiltInElements()` 会补齐缺失；
- 改颜色：`applyCardTint` 会整卡着色（shader），和元素色叠加。

**常见断点**
- 文字不显示：`visible=false`、内容空、被裁剪；
- 换卡后文字串：`textElements` 随卡保存，但内置元素是共享默认。

## 十一、角色卡（读取 / 应用 / 保存 / 切换）

**入口**
- `cards/*.json`（卡快照 + `character`）
- `PlayerCards`（list/read/write/copy/rename/delete/export）
- UI：顶栏选择、管理页新建/重命名/删除

**生效链**
```
selectCard(name)
  ├─ 若在预览态：previewCard = name
  ├─ appliedCard = name；activeCard.set
  ├─ applyCard(name) → applyCardData：读卡字段 + 恢复「全局项」
  ├─ save()（写 client.json；写卡时去掉 chat 段）
  └─ 清缓存：CardCharacter / CardTextures / PortraitSource / PortraitGrade
      → refreshPortraitNow()
```

**波及面**
- 改 `applyCardData` 的“全局项恢复列表”：决定哪些字段切卡不变（chat 必须全在列表里）；
- 改写盘：卡里是否含 `chat`、`character` 是否被覆盖；
- 改 `preferLocal`：多人/单人取哪份。

**常见断点**
- 切卡后聊天样式变了：`chat` 字段漏在恢复列表外；
- 切卡后形象串：缓存没清（四类）；
- `character` 丢失：写卡前没拼回旧段。

## 十二、全局设置与保存

**入口**
- `client.json`、`CommsConfig.save()`、`saveCard()`、自动保存（工坊 400ms 防抖）
- 卡编辑态：`setEditingScreen(true/false)`、`previewCard`

**生效链**
```
CommsConfig.save()
  ├─ 写 client.json（全量，含 chat）
  └─ 写 cards/<activeCard>.json（toJson − chat + 旧 character）
```

**波及面**
- 改 `toJson/fromJson`：旧文件兼容；
- 改保存时机：编辑态误写、切卡覆盖。

**常见断点**
- 改完重开丢了：只改了内存没落盘（控件未调 save）；
- 卡文件被清空：`toJson` 字段缺失 + 未保留 `character`。

## 十三、工坊预览（展示预览 / 屏幕示意）

**入口**
- `CardStudioScreen`：`previewForced`、`editingScreen`、`effectivePreviewCard`
- `CommsHud.renderShowcase`（放大：形象居中、聊天在下）
- `drawMiniScreen`（按 GUI 分辨率换算相对位置）

**生效链**
```
预览开启 → CommsHud.setPreviewForced(true) + CommsConfig.setEditingScreen(true)
  ├─ renderShowcase：portraitOrSelf → drawPortrait / drawChat（放大版）
  └─ drawMiniScreen：直接调 chatRect / portraitRect（同一套布局，含 X 偏移/右间距/基线）
关闭 → setPreviewForced(false) + setEditingScreen(false)
```

**波及面**
- 改 `portraitOrSelf`：预览/演出都可能被顶成本人；
- 改 `previewCard`：预览显示哪张卡；
- 改布局：预览区尺寸影响 showcase 缩放、屏幕示意可用空间。

**常见断点**
- 预览显示玩家自己：卡皮肤未命中 + `boundPlayer` 判定；
- 切页/滚动重影：重建入口没 `clearWidgets()`。

## 十四、演出触发（服务端判定）

**入口**
- 事件：实体/玩家/心跳/快捷键（`ServerStageTriggers`、`StageTriggers`）
- 规则：`stage/<工程>.json` 的 `rules[].when`
- 玩家状态：维度、Y、关键字、名字/UUID、半径

**生效链**
```
游戏事件 → ServerStageTriggers
  ├─ 编码信号（类型 + 参数）
  ├─ StageEngine.match(rule.when, 信号, 玩家状态)
  ├─ StageState.allowed(rule, player)：一次性/冷却/BUSY
  ├─ StagePick：选组（cycle/random/last）
  └─ 目标筛选（自己/附近/全体 + 半径）→ StagePayload 下发
```

**波及面**
- 改 `when` 解析：所有规则；
- 改冷却起点（结束/开始）：玩家体感；
- 改目标筛选：谁能看到演出。

**常见断点**
- 快捷键不生效：画布写 `when` 的组/索引错位；
- 乱触发：组前缀合并、重复规则；
- 不触发：`window`、维度/Y 条件、BUSY。

## 十五、演出播放（客户端时间轴）

**入口**
- `StagePayload` / `ManualPayload` / `ResetPayload`
- `StageClient.apply` → `StagePlayer`
- 台词：`StageScripts.Line`（speaker/text/hold/wait/at）

**生效链**
```
StageClient.apply(payload)
  ├─ 预热：warmup(lines)（预取皮肤/立绘/调色）
  └─ StagePlayer.playGroup / playRule / line
       ├─ 时间轴：at/wait/hold（tick）
       ├─ CommsState.stageShow(speaker, text, hold) → HUD + 出现音
       └─ 结束 → stageStop → 队列恢复
```

**波及面**
- 改 `stageShow`：HUD 显示、音效、队列；
- 改预热：首句卡顿/串皮肤；
- 改 `hold`：与 `chatVisibleLines`/停留设置交互。

**常见断点**
- 演出无声：`stageShow` 未播音（已修）；
- 演出形象错：预热/缓存用了上一张卡；
- 演出卡住：BUSY、wait 未推进、暂停。

## 十六、音效

**入口**
- `blipEnabled`、`newSoundPreset`、`newSoundVolume/Pitch/Speed/FadeIn/FadeOut`
- `goneSoundEnabled`、`goneSoundPreset`、`gone*`
- `soundVolume`、原版「玩家音效」音量
- `ACE_config/sounds/new_message.* / message_gone.*`

**生效链**
```
CommsState.playNewMessage
  ├─ CustomSounds.play(base, preset, volume, pitch, speed, fadeIn, fadeOut)
  │    ├─ 有自定义文件 → 解码播放（JLayer/ PCM）
  │    └─ 无 → CommsSoundSynth 合成预设
  └─ 失败 → 内置 COMMS_BLIP
音量 = soundVolume × 本条音量 × 原版玩家音效音量
```

**波及面**
- 改预设 id：旧配置失效回退；
- 改音量链：所有提示音；
- 改触发点：普通聊天/演出/消失。

**常见断点**
- 没声：开关关、volume 0、原版音量 0；
- 只有内置声：自定义文件格式/时长不合规。

## 十七、画布与保存

**入口**
- `StageCanvasScreen`：节点/连线/文本/触发卡/结束卡/事件组
- `StageProjects`、`StageScripts`、`writeWhen`

**生效链**
```
画布编辑 → persist()
  ├─ 节点 → groups[].lines
  ├─ 触发卡 → rules[].when（writeWhen：leaf / all-any / triggers / hotkey）
  ├─ 结束卡 → rule.effect/cooldown/target/radius
  └─ StageProjects.save(project)
```

**波及面**
- 改 `writeWhen`：所有触发条件；
- 改节点→行映射：演出内容；
- 改组前缀：多链合并/快捷键索引。

**常见断点**
- 保存后条件变了：混用 `when` 写法；
- 删除误伤：前缀匹配（rule1 vs rule10）；
- 首次保存覆盖原条件：`firstCanvasSave` 保护。

## 二十二、排查顺序（出问题先按这个走）

1. **是不是缓存**：换卡/换皮/改调色后不刷新 → 查五个缓存是否清；
2. **是不是全局/卡归属**：切卡后变了/没变 → 查 `applyCardData` 恢复列表与卡文件字段；
3. **是不是预览态**：预览开/编辑态 → `previewCard`、`editingScreen`、`previewForced`；
4. **是不是触发层**：不触发/乱触发 → `when` 写法、组、冷却、目标；
5. **是不是播放层**：触发了但没显示/没声 → `stageShow`、队列、音效开关；
6. **是不是渲染层**：显示了但错位/串 → 几何函数、缩放、纹理；
7. **是不是保存层**：重开丢失 → 控件是否 `save()`、自动保存、`character` 拼接；
8. **是不是安装层**：整个模组不生效/崩 → jar 数量、版本串、热替换。
