## 一、系统定位与边界

- 一个**纯客户端渲染 + 服务端事件驱动**的模组：聊天 HUD、半身像、角色卡、剧本演出。
- 单人 = 集成服务端；多人 = 专用服务端；两者共用同一套服务端触发逻辑。
- modId `acechat`，与旧 SACS 相同 → **两个 jar 不能共存**。
- 只改 `SPEC-SACS`；`SACS` 只读留档。

### 不在范围内
- 不做语音/TTS、不做全屏 CG、不做镜头控制、不做 BGM 播放。
- 不做服务端资源库同步以外的账号体系。

## 二、运行时总览

```
Minecraft 事件 ──► ServerStageTriggers ──► StageEngine(条件匹配)
                          │                      │
                          │                      └─► StageState(一次性/冷却)
                          ▼
                    分组/选组(StagePick) ──► StagePayload ──► 客户端 StageClient
                          │                                        │
                          │                                        ▼
                          │                                 StagePlayer(时间轴)
                          │                                        │
                          │                                        ▼
                          │                              CommsState.stageShow
                          │                                        │
                          ▼                                        ▼
                    ServerAssets(清单/分块)                 CommsHud(绘制)
                                                                   │
                                                    CommsConfig(当前套用的卡)
                                                                   │
                                             PortraitSource / CardTextures / PortraitGrade
```

**分工原则**

| 侧 | 负责 |
|---|---|
| 服务端 | 事件采集、条件匹配、一次性/冷却、选组、下发、资源清单 |
| 客户端 | 只负责“播”（时间轴）、渲染、卡编辑与预览；**不做触发判定** |

## 四、数据契约

### 4.1 目录（游戏版本目录下）
```
ACE_config/
  client.json            全局配置（也是“当前卡”的镜像）
  cards/<卡名>.json      每卡一份完整配置快照 + character
  stage/<工程>.json      剧本工程
  export/                导入导出（含 cards/）
  skins_slim/ skins_classic/ portraits/ filters/ deaths/ sounds/
```

### 4.2 `client.json`
- 全部全局项 + 当前卡快照字段 + `activeCard`。
- **唯一写入口**：`CommsConfig.save()`（同时写 `activeCard` 对应的卡文件）。

### 4.3 `cards/<卡名>.json`
```jsonc
{
  "version": 18,
  "chat": {...}, "portrait": {...},        // 卡内容（整份快照）
  "textElements": [...],                    // 文字元素（含自定义）
  "activeCard": "本卡名",
  "character": {                            // 角色身份（唯一不和配置混用的段）
    "displayName": "", "boundPlayer": true,
    "skin": "slim/xxx.png", "portrait": "xxx.png"
  }
}
```
**约定**：`character` 段只由 `CardCharacter` 读写；`saveCard()` 先读旧文件保留 `character` 再覆盖，禁止丢段。

### 4.4 `stage/<工程>.json`
```jsonc
{
  "name": "...", "type": "sequential", "loop": false, "chunkRadius": 4,
  "groups": [ { "id": "canvas", "lines": [
      { "speaker": "卡名", "text": "...", "start": 0, "at": 0, "hold": 40, "wait": false } ] } ],
  "rules": [ {
      "id": "canvas", "kind": "sequence", "pick": "sequential",
      "play": ["cv_canvas_<hash>_1"], "weights": [50],
      "when": { "triggers": [ { "event": "entity.hurt", "entity": "minecraft:zombie",
                                "group": "cv_canvas_<hash>_1", "op": "all" } ] },
      "repeat": true, "cooldown": 8, "once": "", "target": "nearby", "radius": 4 } ],
  "canvases": { "canvas": { "kind": "sequence", "nodes": [...], "edges": [...] } }
}
```

**时间单位**
| 字段 | 单位 | 说明 |
|---|---|---|
| `hold` | tick | 台词停留；默认 40（2s），画布最小 10 |
| `at` | tick | 台词出现前的停滞 |
| `start` | tick | 相对组开始的偏移（由 hold/at 累加） |
| `cooldown` | **秒** | 从播放结束算起 |
| `window` | tick | 条件窗口，默认 200（10s） |

### 4.5 `when` 的四种写法（**现状，需收敛**）
1. 单叶子：`{"event":"entity.hurt","entity":"..."}`
2. 组：`{"all":[...]}` / `{"any":[...]}`，叶子可含 `not`
3. 触发器数组：`{"triggers":[{event/参数/op/negate/mode/hotkey/group}]}`
4. 表达式：`{"triggers":[...],"expr":"#1 || (#2 && !#3)"}`

**写入口互斥**：
- 画布保存 → `StageCanvasScreen.writeWhen`（只写 1/2/3 中它负责的形态）；
- 触发器页 → `StageTriggers`（保留 op/negate/mode/hotkey）；
- 表达式由触发器页维护，画布遇到 `expr` **必须不动**。

### 4.6 组前缀
`groupPrefix() = "cv_" + safe(ruleId) + "_" + hash(chain)`；按触发卡拆组时追加 `_N`。
**任何组 id 的生成只能走 `groupPrefix()`**，禁止手拼。

### 4.7 网络包
| 包 | 方向 | 语义 |
|---|---|---|
| `StagePayload` | S→C | 已解析好的 lines + rule + loop |
| `ManualPayload` | C→S | 按下的触发器 index（对应 `when.triggers[i]`） |
| `ResetPayload` | C→S | 清掉某规则在某玩家身上的一次性记录 |
| `AssetManifestPayload` / `AssetChunkPayload` / `AssetRequestPayload` | S→C / 双向 | 角色资源清单与分块 |
| `StatsPayload` | S→C | 在线玩家数值快照 |

## 五、关键流程

### 5.1 渲染管线（`CommsHud.render`）
```
autoApplyCardFor(当前显示者)        // 演出时强制套说话人的卡；编辑时暂停自动切卡
  └─ renderInternal
       ├─ portraitOrSelf           // 预览只替换“自己”；演出保持说话人
       │    └─ PortraitSource.resolve
       ├─ drawPortrait
       │    ├─ applyCardTint(调色乘法色)
       │    ├─ 面板/背景板/照片框
       │    ├─ 立绘 或 调色烘焙(SkinBustRenderer)
       │    ├─ 文字元素（白字前先还原 shader 色）
       │    └─ PortraitFilters（铺满整框）
       └─ drawChat（折行 → 背景 → 名字/正文）
restoreEditingCard()               // 只在编辑界面里还原，游戏里不还原
```

**卡解析优先级（`PortraitSource.resolve`）**
1. 本机预览覆盖“自己” → 预览卡；
2. 卡文件存在 → 卡 `character`（单人/作者本机用本地卡，`preferLocal`）；
3. 卡皮肤：`preview || !boundPlayer || !realPlayer` 时用卡皮肤；
4. 卡立绘（`customPortraitEnabled`）；
5. 在线玩家皮肤 / 默认皮肤。

**缓存层（改这里必查）**
| 缓存 | 键 | 失效 |
|---|---|---|
| `CardCharacter.CACHE` | 卡名 | 文件 mtime |
| `CardTextures` | `skin:/portrait: + 引用` | 文件 mtime、`clearAll()` |
| `PortraitSource.CACHE` | 玩家 UUID | 卡文件 mtime、`clear()` |
| `PortraitGrade.CACHE` | 皮肤纹理 + slim + `gradeKey` | 参数变化自动换键；失败 5s 后重试 |
| `CommsState.portrait` | 当前说话人 | 换人、`refreshPortrait()` |

### 5.2 演出链路（服务端）
```
事件 → Signal → BUFFER(窗口裁剪)
  → 每条规则 StageEngine.matches
  → StageState.allowed(once/cooldown)     // 手动/快捷键跳过
  → 选组：有 when.triggers[i].group 就用匹配到的组，否则 rule.play
  → dispatch：算接收者(self/nearby/all)、排队、BUSY
  → StagePayload
```
- 心跳 `tick.every`：每 tick 发一次，**只在 `now % every == 0` 且是当前 tick 时才成立**；`every` 缺省 20。
- 手动/快捷键：`manual()` 不查 once/cooldown/BUSY，按键即演；播着再按从头重播。

### 5.3 画布保存链路（客户端）
```
persist()
  ├─ canvases[currentRule] = {nodes, edges}
  ├─ rebuildPlayback(root)
  │    ├─ 随机组：每句一个组
  │    ├─ 顺序组：每张触发卡一条链 → 一组 cv_<..>_N；play=[组...]
  │    │    （没有可播对白 → clearCanvasPlayback）
  │    ├─ pruneCanvasGroups(清旧组)
  │    ├─ canvasPlay(保留非本画布组)
  │    ├─ writeWhen(触发器条目带 group/op/negate/hotkey)
  │    └─ applyEndSettings(repeat/cooldown/once/target/radius)
  └─ StageProjects.writeProject
```

### 5.4 卡应用链路
```
selectCard / autoApplyCardFor / 演出切换
  → applyCard(卡名)
     → applyCardData：存全局项 → apply(卡) → 还原全局项 → activeCard=卡名
```
- **全局项**（聊天框、音效、名单、素材目录、模板）永远不被卡改。
- **卡项**（portrait 几何/调色/滤镜/文字元素/半身像）随卡走。

## 六、不变量（Invariant，违反必出 bug）

1. **磁盘写入单入口**：`client.json` 只能由 `CommsConfig.save()` 写；卡文件只能由 `CommsConfig.save()/saveCard()` 与 `CardCharacter.write()` 写。
2. **`character` 段不参与卡应用**，只由 `CardCharacter` 读写；`saveCard` 必须保留它。
3. **`when` 只有一个主人**：有 `hotkey`/`expr` 的规则，画布不得改写；表达式由触发器页维护。
4. **组 id 只用 `groupPrefix()`**；画布组必须能被 `clearCanvasPlayback` 用同一前缀清掉。
5. **渲染线程不读磁盘**：文件读取只在 `resolve/load` 层，并且必须走缓存。
6. **调色烘焙的取像素顺序**：当前纹理 → 资源管理器 → 玩家 profile 下载。反过来会把卡皮肤换成玩家皮肤。
7. **预览只替换“自己”**：演出/别人发言时 `portraitOrSelf` 必须返回说话人的 source。
8. **游戏运行中禁止覆盖 jar**（SecureJar 映射会导致 `NoClassDefFoundError`）；安装只用 `install.ps1`。
9. **卡皮肤判定**：`preview || !boundPlayer || !realPlayer`，不要改回只看 `boundPlayer`。
10. **单人/作者本机优先本地卡**（`preferLocal`），多人无本地卡才用服务端下发。
11. **界面入口唯一**：所有“打开配置”的入口（快捷键、选项界面按钮、聊天/背包里的按钮）必须指向同一个屏幕；改 UI 时必须全局搜 `setScreen(new`，不能只改快捷键那条。
12. **重建界面先清空，且只有一条重建路径**：任何会重排控件的动作（`init()`、切页签、切卡、滚动、拖滚动条、窗口尺寸变化）都必须走**同一个重建方法**，该方法第一行 `clearWidgets()`，然后重建所有常驻控件（列表/锚点/按钮）；**禁止在已有控件上追加或只挪坐标**。同一信息只画一次（控件自带文字就不要再叠一层标签）。

## 七、Bug 根因库（按症状归组）

> **规则（强制）**
> 1. 每发现一个**新根因**，必须补进本表对应症状下，写明：现象、根因、检查点、修复点。
> 2. 改到相关区域时，**把该症状下的所有可能原因逐条排除**（不是只修这次命中的那个），并在交付说明里写“排除了哪些”。
> 3. 同一症状下的原因会互相掩盖（修好 A 才暴露 B），所以“改完还不对”优先怀疑本表里没排除的条目，而不是新增原因。

### 7.1 形象 / 皮肤（症状：显示成玩家本人、卡皮肤不生效、偏色、改了不刷新）

| # | 可能根因 | 检查点 / 修复 |
|---|---|---|
| 1 | 调色烘焙取像素顺序错误（先下 profile 皮肤） | `PortraitGrade.startBake`：current texture → resource → profile |
| 2 | 卡皮肤判定只看 `boundPlayer` | `preview \|\| !boundPlayer \|\| !realPlayer` |
| 3 | 演出用远程副本覆盖本地卡 | `CardCharacter.preferLocal` |
| 4 | `PortraitSource`/`CardCharacter`/`CardTextures` 缓存未失效 | mtime、`clearAll()`、`clearCache()` |
| 5 | 调色/双色调参数本身偏色 | 卡片「双色调」开关、色号、`PortraitGradeMath` |
| 6 | 烘焙缓存被逐帧清空 / 失败永久拉黑 | `applyCardData` 不 invalidate；失败 5s 重试 |
| 7 | 预览把说话人顶掉 | `portraitOrSelf` 只替换“自己” |
| 8 | 显示名映射导致卡查找失败 | `autoApplyCardFor` 先按原名再按显示名 |
| 9 | 编辑态预览覆盖舞台说话人（2026-11-17） | `CommsHud.portraitOrSelf` 在 `editingScreen` 时无条件换成预览卡；修：`CommsState.stageActive()` 期间永不替换 |
| 10 | 调色烘焙线程异常/回调丢失后 `PENDING` 永久卡住（2026-11-18） | 线程体必须 try/catch 收尾 + `STARTED` 15 秒看门狗；失败时 `PortraitSource.invalidate(sender)` 让下次重新取纹理 |
| 11 | 立绘调色缓存写入键与查询键不一致（2026-11-18） | `PortraitFiles.texture` 查询 `name#gradeKey` 却 `LOADED.put(name)`，导致每帧重烘焙；修：按同一 key 写，并更新 `LAST_BAKE/LAST_TEXTURE` |

### 7.2 预览 / 编辑界面（症状：预览不刷新、显示旧卡、切页残留、滚动重叠、输入丢焦点）

| # | 可能根因 | 检查点 / 修复 |
|---|---|---|
| 1 | 重建路径未清空控件（init / 切页 / 滚动 / 拖条 / 改窗口） | 统一重建方法，第一行 `clearWidgets()` |
| 2 | 同一条信息画两遍（控件自带 + 额外标签） | 标签单一来源 |
| 3 | `CommsState.portrait` 旧缓存 | `refreshPortraitNow()` |
| 4 | `editingScreen` 未置位/未复位 | 构造/init 置 true，onClose/removed 置 false |
| 5 | 预览区控件只读（没有拖动实现） | 拖动功能未实现属于缺失，不是 bug |
| 6 | 滚动后控件坐标与标签坐标不同源 | 两遍布局共用同一 `cursorY` |
| 7 | 预览框写死不读配置（2026-11-17） | `renderShowcase` 固定 150×1.22；修：按 `portraitWidth/Height/Scale` × 预览倍率等比适配 |
| 8 | 示意与真实布局两套算法（2026-11-17） | `drawMiniScreen` 自算、漏 `centerXOffset/chatRightGap/+6`；修：直接复用 `chatRect/portraitRect` |
| 9 | 列表只渲染前 8 条（2026-11-17） | `Math.min(8,size)`；修：取消上限，交给页内滚动 |
| 10 | 取色每像素写盘 / 关界面不补写（2026-11-17） | `applyColor` 内 `save()`；`onClose/removed` 无 flush；修：松手提交 + 关闭必 flush |

### 7.3 演出触发（症状：快捷键不生效、不触发、乱触发、播报范围不对）

| # | 可能根因 | 检查点 / 修复 |
|---|---|---|
| 1 | `when` 写法混用（leaf / all-any / triggers / expr） | 只由 `writeWhen` 或 `StageTriggers` 写，互斥 |
| 2 | 触发器索引错位（`#n` 与数组下标） | `ManualPayload.index` 与 `triggers[i]` 对齐 |
| 3 | 组前缀/多链合并 | `groupPrefix()` + 每触发卡独立组 |
| 4 | 一次性/冷却/BUSY 拦截 | `StageState.allowed`；手动触发跳过 |
| 5 | 窗口 `window` 太小/太大 | 默认 200 tick |
| 6 | 服务器未重载工程（缓存） | `refreshProjects`、重载工程按钮 |
| 7 | 一次性事件信号留在 60 秒缓冲里，周期 fire 反复命中（2026-11-18） | 击杀/受伤/聊天等信号只允许触发同一条规则一次；`tick.every` / `player.lowHealth` 例外，仍按冷却重复 |

### 7.4 画布（症状：排列乱、保存后触发条件变了、删除误伤）

| # | 可能根因 | 检查点 / 修复 |
|---|---|---|
| 1 | 前缀匹配没加边界（rule1 vs rule10） | `endsWith` / 精确 id |
| 2 | 首次保存覆盖原 `when` | `firstCanvasSave` 保护 |
| 3 | 有 `hotkey`/`expr` 时画布仍写条件 | `writeWhen` 直接返回 |
| 4 | 多触发卡合并成一场 | 每卡独立组 + `group` 字段 |

### 7.5 安装 / 崩溃（症状：启动崩、`NoClassDefFoundError`、jar 不生效）

| # | 可能根因 | 检查点 / 修复 |
|---|---|---|
| 1 | 游戏运行中覆盖 jar | `install.ps1` / `switch-to-*.ps1` 的关闭检查 |
| 2 | 两个同 modId 的 jar 同时在 mods | 切换脚本保证只留一个 |
| 3 | 装的是旧包 / 未重启 | 比对 jar 哈希、看日志版本串 |
| 4 | 模组列表里版本串对不上 | 日志 `Mod List` 行 |

### 7.6 卡数据（症状：卡不同步、预览/演出用旧内容、文字元素串卡）

| # | 可能根因 | 检查点 / 修复 |
|---|---|---|
| 1 | 卡 = 整份配置快照，边界模糊 | 分层改造（大纲 P1） |
| 2 | 写盘入口不唯一 | `CommsConfig.save/saveCard`、`CardCharacter.write` |
| 3 | `character` 段被覆盖丢失 | `saveCard` 保留旧段 |
| 4 | 远程副本优先 | `preferLocal`（单人/作者本机） |
| 5 | 卡改名/复制不重写 `nameColors[].name`（2026-11-17） | `PlayerCards.copyCard/rename` 只搬 JSON；修：条目名随卡名重写 |
| 6 | 保存非原子、双写（2026-11-17） | `Files.writeString` 直接覆盖；修：临时文件 + `ATOMIC_MOVE` |
| 7 | 自动保存只覆盖显示名（2026-11-17） | 工坊只有 `displayName` 走 400ms；其余控件即时写；修：关界面统一 flush |
| 8 | 渲染期临时套用了别人的卡时保存，把别人卡内容写回 activeCard（2026-11-17） | `autoApplyCardFor` 只改 `appliedCard`；择时保存前必须确认 `appliedCard == activeCard`，否则只写 `client.json`，不写卡文件 |
| 9 | 打开工坊时没重新套用选中卡，内存残留渲染期套用的别人卡（2026-11-17） | `CardStudioScreen.init` 里若 `appliedCard != selected`，先 `applyCardForEditing(selected)`，否则标题是自己的卡、文字元素却是别人的 |

### 7.7 名字 / 符号（症状：名字颜色不命中、符号颜色无效、条目删不掉）

| # | 可能根因 | 检查点 / 修复 |
|---|---|---|
| 1 | 名字颜色按“卡名”匹配，普通玩家消息按玩家名 | `CommsConfig.nameColor(uuid,name)`；演出说话人＝卡名时才命中 |
| 2 | 符号颜色只作用于原版聊天回放 | `CommsHud.buildLines` 用 `nameStyle`（2026-10-14 要求“符号跟名字同色”）；UI 文案须注明 |
| 3 | 条目名固定＝卡名、无改名入口 | 工坊文字页 `new NameColor("", selected, …)`；卡改名联动见 7.6#5 |
| 4 | 未命中条目只能回退全局默认色（2026-11-17） | 独立卡/未配玩家无法单独上色；修：卡字段 `cardNameColor` 作为二级回退（条目 → 本卡 → 全局） |

### 7.8 音效 / 资源（症状：同句不响、静音后仍有声、首句缺皮）

| # | 可能根因 | 检查点 / 修复 |
|---|---|---|
| 1 | 舞台音效判重只比文本 | `CommsState.stageShow`；修：`speaker + text` 一起比 |
| 2 | 回落声不走“玩家音效”音量 | `play(COMMS_BLIP)` 用 `forUI`（MASTER）；修：手动乘 `SoundSource.PLAYERS` |
| 3 | 预热不触发远端资源请求 | `StageClient.warmup` 只读本地；`AssetRequest` 由清单触发；修：远端缺字节时跳过本地加载 |

## 十、架构演进路线（按收益排序，一次一块）

### P1 · 卡数据分层（最高优先）
- 目标：卡只存**差异**，全局存默认；`character` 独立成节。
- 收益：一次解决“卡不同步 / 预览被覆盖 / 调色串卡”。
- 风险：旧卡迁移（读旧格式 → 生成新格式，保留备份）。

### P2 · 条件模型收敛
- 目标：只保留 `triggers[]` 一种写入；`expr` 作为可选；画布与触发器页共享同一模型。
- 收益：消除“两套写入口互相覆盖”。
- 风险：老工程的 `all/any` 需要一次性迁移。

### P3 · UI 拆分
- `CommsConfigScreen` → 按 tab 拆组件 + 行构建器；
- `StageCanvasScreen` → 渲染 / 交互 / 序列化 三层。
- 收益：改一个功能只动一个文件。

### P4 · 服务端/客户端边界
- `ServerStageTriggers` 拆「事件采集」「规则匹配」「下发队列」；
- 客户端不读工程文件（除本地编辑）。
